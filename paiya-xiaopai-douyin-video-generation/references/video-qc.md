## 目录

1. 三层职责

3. 结构层：可拍性

---

## 1. 三层职责

| 层 | 查什么 | 能否自动 | 失败后果 |
|---|---|---|---|
| 规则层 | 违禁词、功效宣称、绝对化、站外引流 | 可全自动 | BLOCK |
| 结构层 | 分镜表完整性、时间码、镜头时长、口播字数 | 可全自动 | BLOCK / WARN |
| 覆盖层 | 三卖点、必现场景、事实数字、三版互斥 | 半自动，需人工确认语义 | WARN |

---

## 2. 规则层

### 硬阻断（命中即 BLOCK）

| 类别 | 示例 |
|---|---|
| 功效宣称 | 减肥、燃脂、瘦身、提神醒脑、治疗、治愈、增强免疫力 |
| 绝对化 | 最好、第一、全网最低、唯一、100% |
| 站外引流 | 加微信、私信领券、淘宝搜、主页看链接 |
| 贬低竞品 | 其它品牌都是垃圾、比 XX 难喝 |
| 未授权背书 | 检测报告、获奖、医生推荐（brief 未提供时） |

### 需人工确认（WARN）

- 「最」字与评价词搭配（最划算 / 最推荐）——即便语气口语，也建议改写。
- 对比价格时点名具体门店品牌。
- 咖啡因相关的体感描述（心慌、睡不着），属敏感体感。

### 替换建议库

| 原表述 | 建议 |
|---|---|
| 提神醒脑 | 早上来一条，人清醒点（描述场景，不承诺功效） |
| 全网最低 | 本次活动 69 元，比日常便宜 30 元 |
| 减肥也能喝 | 0 糖 0 脂，减脂期解馋用 |
| 最好喝 | 我自己回购了三盒（主观偏好，非绝对化） |

## 3. 结构层

| 检查项 | 判据 | 不通过 |
|---|---|---|
| 分镜表列数 | 9 列齐全（镜号/时间码/时长/景别/画面/台词/字幕/音效/转场） | BLOCK |
| 时间码连续 | 从 0 开始，相邻镜首尾相接，误差 ≤0.5s | BLOCK |
| 总时长 | 与 brief 时长偏差 ≤2s | BLOCK |
| 单镜时长 | ≤5s | WARN（>6s 则 BLOCK） |
| 镜头数 | 30s 档 8–14 个 | WARN |
| 前 3 秒钩子 | S1 结束 ≤3s，且台词或字幕非空 | BLOCK |
| 口播字数 | ≤ 时长 × 5（30s ≤150 字） | BLOCK |
| 镜头时长与台词匹配 | 每镜字数 ≤ 该镜时长 × 5 | WARN |
| 比例标注 | 含 9:16 | WARN |
| 产品与价格落地 | 最后一镜或倒数第二镜含产品名 + 价格 | BLOCK |

**为什么单列「镜头时长与台词匹配」**：这是视频脚本最常见的隐性错误——3 秒镜头写 25 个字，拍出来必然赶，剪辑只能砍信息。

## 4. 覆盖层

| 检查项 | 判据 |
|---|---|
| 三卖点落地 | 台词或字幕中出现全部 required_points；可用同义词（0糖=0 蔗糖） |
| 画面证明 | 至少一条卖点有对应画面（撕开 / 倒水 / 计时 3 秒） |
| 事实数字 | 出现的数字必须在 `numbers_allowlist` 或可复算；锚点与时间码不计 |
| 禁用内容 | 未出现 brief 禁止的场景、竞品、认证 |
| 三版互斥 | 钩子类型、口播占比、主推卖点、结尾方式四项均不同 |
| 平台适配 | 竖屏构图、字幕安全区、挂车位置有说明 |

数字检查要剔除：镜号（S1）、锚点（V1-S2）、时间码（3-6s）、时长（3s）。仅保留台词、字幕、画面里的内容数字。

---

## 5. 结论与修复循环

| 结论 | 条件 | 动作 |
|---|---|---|
| PASS | 无 BLOCK、无未处理 WARN | 可展示 |
| WARN | 仅有 WARN | 展示时必须带 WARN 清单与建议 |
| BLOCK | 任一 BLOCK | 不展示，修复后重跑，最多 3 轮 |

3 轮后仍 BLOCK → 向用户说明卡在哪一条，给两个可选方向，不硬交付。

---

## 6. 报告格式

````markdown
**V1 质检：PASS**
- 结构：9 列完整｜时间码 0–30s 连续｜11 镜｜最长 4s｜口播 132 字（上限 150）
- 规则：0 命中
- 覆盖：卖点 3/3｜画面证明 2 处｜数字 5 个（4 个来自 brief，1 个可复算）
- WARN：S7 字幕 19 字，建议压到 18 字内
````

报告必须能给到「哪一镜、哪个字段、改成什么」，不能只写「建议优化」。

---

## 7. 降级

- 质检脚本不可用 → 人工按本文件逐条过，并在成品卡标注「质检为人工执行」。
- brief 缺失关键字段（时长、比例）→ 用默认 30s / 9:16，并标注「默认值，待确认」。
- 用户坚持要写 brief 禁止的内容 → 拒绝该条，给出合规替代，不静默改写。
