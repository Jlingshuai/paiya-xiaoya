# 抖音视频脚本生成（派芽 · 小派 POC）

## 概述

把「一条 30 秒抖音商单视频」拆成可验证的七阶段链路：判定要不要写、写图文还是视频 → 把 brief 变成视频事实卡 → 装配抖音画像与赛道热点 → 三种叙事形式各出一版分镜 → 逐版质检 → 展示并落成品卡 → 按镜号/秒数定点改写。

**POC 边界（必须向用户说明）**：

- 画像、热点、brief 三处为 MOCK（美食赛道），数据在 `references/mock/`，不代表真实接口结果。
- 本技能只生成抖音竖屏短视频脚本（30 秒档为默认）；识别到小红书图文笔记时转交 `paiya-xiaopai-xhs-generation`。
- 小红书视频暂不覆盖：用户要求「小红书视频」时如实说明本期视频分支只做抖音，不静默改写平台。
- 不负责拍摄、剪辑、生成视频画面，只产出可执行分镜与口播稿。

**与图文技能的边界**：

| 维度 | 图文技能 | 本技能 |
|---|---|---|
| 平台 | 小红书 | 抖音 |
| 产出 | 标题 + 正文 + 话题 | 分镜表 + 台词 + 字幕 + 音效 |
| 锚点 | T / C / B1–B6 / H / P | HOOK / COVER / S1–Sn / CAP |
| 质检重点 | 字数 350–700、卖点落地、违禁词 | 时间码、单镜 ≤5s、口播 ≤ 时长×5、卖点落地 |
| 三版差异 | 说服路径 | 叙事形式与口播占比 |

---

## 核心原则

1. **前 3 秒定生死**：钩子必须是数字、冲突、动作或提问，不允许 logo、空镜、自我介绍开场。
2. **必须能拍**：每一镜写清谁、在哪、做什么；写「氛围感」等于没写。
3. **台词要念得完**：3 秒镜头配 20 字必然赶，字数按 4–5 字/秒倒推。
4. **三版是三种拍法**：口播测评、剧情演绎、沉浸式跟拍，不是同一稿改措辞。
5. **改写落到镜号**：用户说「第 3 到 5 秒」，先定位到具体镜头，只动那一行。
6. **不许编事实**：价格、成分、咖啡因、限量数字只能来自 brief；功效词一个都不碰。

## 工作流程

| 阶段 | 名称 | 产出 | 确认门 |
|---|---|---|---|
| 零 | 意图与形态判定 | 意图、形态、分数、证据 | 40–69 二判；形态不明时确认一次 |
| 一 | Brief 解析（仅商单） | 视频事实卡 | 用户确认事实卡 |
| 二 | 画像与热点装配 | 装配摘要（≤200 字） | 无（异常时标注降级） |
| 三 | 三版分镜生成 | 3 版完整分镜表 | 无 |
| 四 | 三层质检 | 每版结论 + 命中清单 | BLOCK 时修复，最多 3 轮 |
| 五 | 展示与成品卡 | 三张版本卡片 + 卡片页 + Markdown 成品卡 | 用户选版或提修改 |
| 六 | 定点改写 | 新版本 + 版本链 | 每轮改完复检 |

## 阶段零：意图与形态判定

**先跑脚本，不要凭感觉判断。**

```bash
python3 scripts/intent_score.py --text "<用户原话>" [--attachment] [--in-flow] [--commercial]
```

输出 `intent`、`modality`、`platform`、`score`、`layers`、`evidence`、`handoff`、`notes`。规则全文见 `references/intent-rubric.md`。

### 0.1 五条前置规则（命中即结束）

| 顺序 | 条件 | 动作 |
|---|---|---|
| ① | 已在脚本链路中（等补字段／等选版／改写中） | `--in-flow`，直接续接；有改动动词 + 指代版本或秒数 → `rewrite` |
| ② | 显式拒绝（「不用写」「先不生成」） | 退出技能 |
| ③ | **形态判定** | `handoff_article`：识别为小红书图文笔记 → 读并转交 `paiya-xiaopai-xhs-generation`。`confirm_modality`：图文与视频信号冲突、或只说「写个脚本」 → 只问一次「要小红书图文笔记，还是视频脚本（抖音）？」。小红书视频 → 说明本期视频只覆盖抖音，不静默换平台 |
| ④ | 评估诉求（「看看这条视频」「为什么没流量」）且无创作动词 | 只出评估，不生成、不写版本链 |
| ⑤ | 方法论提问（怎么起号、完播率怎么提、几点发） | 按日常问答，不进入链路 |

**为什么形态要前置**：分镜表和图文正文零交集。把要图文的人拉进分镜流程，用户拿到一堆「S1/S2」无法发布；反之给要视频的人三篇笔记，等于整轮返工。

### 0.2 三层打分与阈值

| 层 | 内容 | 上限 |
|---|---|---|
| 第一层 | 硬信号：抖音 +20、创作动词 +20、视频对象 +15、brief 附件 +25、商单词 +20、时长/条数 +10 | 65 |
| 第二层 | 关键词密度：创作动词族、内容要素词、平台词密度 | 30 |
| 第三层 | 扣分：方法论 −25、诊断 −20、寒暄 −40、只有平台词 −10 | — |

- **≥70**：直接触发。
- **40–69**：LLM 二判（`temperature=0`，只答是／否），「是」才触发。
- **<40**：按日常问答。
- **强形态例外**：出现「分镜／口播稿／视频脚本」且有创作动词时，无需平台词也直接触发——这类词几乎没有歧义。
- **带 brief 例外**：商单请求落在 40–69 时直接触发。

### 0.3 四种走向

| 走向 | 判定 | 处理 |
|---|---|---|
| **商单创作** | 有 brief 附件，或显式「商单／合作／brief／品牌方／挂车」 | 走阶段一解析 brief，再生成 |
| **日常创作** | 无 brief，用户要一条视频但无产品信息 | 跳过阶段一，只用画像 + 热点；不得写价格功效事实 |
| **日常聊天** | `chat` / `evaluate` | 退出技能，正常对话或出评估报告 |
| **图文分支** | `handoff_article` | 不在本技能内生成，转交 `paiya-xiaopai-xhs-generation` |
| **待确认** | `confirm_modality` | 只问一次图文还是视频，答完立即路由 |

**商单但无 brief**：要求上传或贴文字，给最少信息清单（产品是什么、卖点 1–3 条、卖给谁、视频多长、是否口播）。不得编产品，也不得静默降级成日常模式。

## 阶段一：Brief 解析（仅商单）

完整字段表与追问话术见 `references/brief-extraction.md`。

1. **读取**：PDF 用 `pdf` Skill，Word 用 `word` Skill，Excel/CSV 用 `sheet` Skill，PPT 用 `ppt` Skill，图片先 OCR，纯文本直接读；链接先判域名。
2. **抽字段**：品牌、产品、品类、卖点 1–3、目标人群必填；价格、规格、场景、竞品禁区、内容要求选填；**视频必抽**时长、比例、口播人、挂车、报备。
3. **出事实卡**：表格展示，字段 / 值 / 原文片段 / 是否缺失。
4. **确认门**：事实卡确认后才生成；只改被点名字段，不重跑整份解析。
5. **缺失追问**：一次最多 3 项，按影响排序；用户说「你定」→ 默认 30s、9:16、真人口播，并在事实卡标注默认值。
6. **完全无信息**：请用户上传 brief 或贴文字，不生成任何内容。

POC 演练用 `references/mock/mock-video-brief.md`，解析结果应与 `mock-video-fact-card.json` 一致。

## 阶段二：画像与热点装配

```bash
python3 scripts/fetch_context.py --red-id R-2048-DY --track 美食 --compact
```

- 画像取：赛道、人设一句话、语气、平均完播率、擅长形式、语速、镜头节奏、钩子偏好、观众核心需求。
- 热点取：4 条同赛道视频的 `hook / body / ending` 结构、`reusable` 与 `not_reusable`、`saturation_warnings`。
- **只借结构**：钩子类型、叙事骨架、镜头节奏、字幕分工。不抄标题原句、不抄画面、不抄他人数据。
- **撞车规避**：`saturation_warnings` 命中的开头方式，必须换一种。当前警告：「3 秒冲咖啡」动作三连已饱和、「同事以为我点外卖」误会式开头已滥用。
- 接口失败时显式降级，成品卡写「热点未接入，本版未参考热点」，不假装参考过。

## 阶段三：三版分镜生成

结构规范全文见 `references/video-schema.md`。每版固定格式：

```markdown
### V1｜口播测评（30 秒）

- **定位**：给谁看、解决什么、为什么信
- **时长 / 比例**：30s｜9:16 竖屏
- **前 3 秒钩子**：画面 + 第一句台词
- **口播总字数**：xx 字（上限 150）
- **卖点落点**：S2 价格 / S4 成分 / S6 冲泡

| 镜号 | 时间码 | 时长 | 景别 | 画面 | 台词 / 口播 | 字幕 | 音效 / BGM | 转场 |
|---|---|---|---|---|---|---|---|---|
| S1 | 0-3s | 3s | 近景 | ... | ... | ... | ... | 硬切 |

- **拍摄清单**：场景、道具、人员、光位
- **事实引用**：列出用到的 brief 事实与数字
```

### 三版策略（必须互斥）

| 版本 | 叙事形式 | 口播占比 | 前 3 秒手法 | 主推卖点 |
|---|---|---|---|---|
| V1 | 真人口播测评 | >70% | 直接抛数字或结论 | 价格 / 成分 |
| V2 | 剧情演绎（冲突/误会） | 30–50% | 第三方提问或冲突台词 | 场景 / 性价比 |
| V3 | 沉浸式跟拍 / 动作流 | ≤10% | 动作或声音先行 | 冲泡体验 / 质感 |

**五条硬约束**：钩子类型不重复；口播占比必须分三档；开场连续 6 字不跨版重复；主推卖点不完全相同；结尾不能三版都是「价格 + 下单」。

违反任一条，重写该版，不带病展示。

## 阶段四：三层质检

```bash
python3 scripts/video_qc.py --file "<成品卡.md>" --version V1
python3 scripts/video_qc.py --file "<成品卡.md>" --version V2
python3 scripts/video_qc.py --file "<成品卡.md>" --version V3
```

**必须逐版跑**，整份跑会把版本号、时间码、元信息数字当成事实数字误报。

| 层 | 检查 | 结论 |
|---|---|---|
| 规则层 | 功效词、绝对化、站外引流、贬低竞品、未授权背书 | 命中 BLOCK / WARN |
| 结构层 | 9 列完整、时间码连续、总时长 ±2s、单镜 ≤5s、前 3 秒钩子、口播字数、镜头与台词密度、比例标注、结尾产品与价格 | BLOCK / WARN |
| 覆盖层 | 三卖点落地、画面证明、数字白名单、三版互斥 | WARN，需人工确认语义 |

- PASS → 可展示；WARN → 展示时带清单；BLOCK → 不展示，修复后重跑，最多 3 轮。
- 3 轮仍 BLOCK → 说明卡在哪条，给两个可选方向，不硬交付。

## 阶段五：展示与成品卡

**默认先给卡片，再给留档。** 不要把整份 Markdown 直接甩给用户。

### 5.1 对话内卡片（每版一张）

| 区块 | 写什么 |
|---|---|
| 卡头 | `V1｜口播测评｜30s｜9 镜｜口播 86 字｜PASS` |
| 前 3 秒 | 画面 + 第一句台词，压成一行 |
| 主推卖点 | 一条主推 + 三条落地镜号（如 S2 价格 / S5 成分 / S6 活动） |
| 结尾 | 最后一镜怎么收 |
| 操作 | 「展开分镜」「改这一版」「复制口播」 |

三张卡依次排列，卡间空一行；完整分镜默认折叠，用户点「展开」或说「看 V2 全部」再展开。卡片只写决策信息，不铺满 9 列。

### 5.2 卡片页（需要并排比较时）

生成单文件 HTML：三版各一张卡，卡头、钩子、口播字数、质检结论直接露出，分镜表点开看；顶部切换版本，底部「对比三版」。文件名 `抖音三版脚本卡片.html`，放任务目录后用 `present_files` 交付。卡片页是展示层，不改脚本内容。

### 5.3 Markdown 成品卡（留档）

仍落 `.md`，作为可版本管理的底稿；展示顺序是 **对话卡片 → 卡片页 → md**，不要一上来给 md。

```markdown
# 抖音视频脚本_山栖冷萃咖啡液_20261111

## 元信息
## 装配摘要（画像 / 热点 / brief，含降级说明）
## 三版脚本（### V1｜… / ### V2｜… / ### V3｜…）
## 质检报告（逐版结论 + 命中清单 + 数字人工判定）
## 版本链
## 依据链（哪条来自 brief，哪条来自画像，哪条来自热点结构）
## 待补充项
```

## 阶段六：定点改写

1. **解析指代**：版本（第一个/第二个/V2）+ 位置（标题/开头/第 3–5 秒/结尾）+ 改动类型（换/加/删/调语气）。
2. **秒数转镜号**：按时间码落镜；跨镜就改涉及的每一镜，不多不少。
3. **只改锚点**：其余行逐字保留；需要联动时（改台词导致字数超限）只压该镜字幕或拆镜，不重写全篇。
4. **复检**：改完立即跑该版 `video_qc.py`，结论写进版本链。
5. **版本链**：`V2 → V2.1（改第 3–5 秒画面）→ V2.2（压口播字数）`。

**定位不到**（秒数落在空档、版本不存在、指代有歧义）→ 回问一句，不猜。

## 异常与降级

| 场景 | 处理 |
|---|---|
| 画像接口不可用 | 只用 brief + 热点生成，成品卡标注「画像未接入，未做人群适配」 |
| 热点接口不可用 | 只用 brief + 画像，标注「热点未接入；开头方式未做撞车校验」 |
| 两者都不可用 | 仅按 brief 生成，标注降级；不假装参考过 |
| brief 缺时长/比例 | 默认 30s / 9:16，标注「默认值，待确认」 |
| 质检脚本不可用 | 人工按 `video-qc.md` 逐条过，成品卡标注「质检为人工执行」 |
| 用户要求写功效 | 拒绝该条，给合规替代，不静默改写 |
| 用户要求小红书视频 | 说明本期视频只覆盖抖音，可转图文技能或按抖音出稿 |
| 三版无法互斥 | 重写第三版，不靠改措辞凑差异 |
