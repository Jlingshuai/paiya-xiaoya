# 小红书图文脚本生成（派芽 · 小派 POC）

## 概述

把「一次小红书图文笔记创作」拆成可验证的七阶段链路：判定要不要写 → 把 brief 变成事实卡 → 装配红人画像与赛道热点 → 三策略各出一版 → 逐版质检 → 展示并落成品卡 → 支持锚点化多轮改写。

**POC 边界（必须向用户说明）**：

- 画像、热点、brief 三处为 MOCK（美食赛道），数据在 `references/mock/`，不代表真实接口结果。
- 本技能只生成小红书图文笔记；识别到抖音视频脚本时转交 `paiya-xiaopai-douyin-video-generation`，不在本技能内硬写分镜。
- 不负责发布、不负责图片生成，只产出文案与配图建议。

**与产品七阶段链路的对应**：本技能把设计稿的「02 意图识别」前置为阶段零，「01 接入与解析」到「07 交付与留档」依次落到阶段一至阶段五；「05 选择与微调」与「06 质检」合并为阶段四复检 + 阶段六改写闭环。

---

## 核心原则

1. **不许编事实**：价格、成分、工艺、功效、认证只能来自 brief；缺失就写 `【待补充】` 或整段不写。
2. **三版必须互斥**：三版走不同说服路径，不是同一篇的三个措辞。
3. **改写必须定点**：只动被点名的锚点，其余逐字不变。
4. **展示即带质检**：每版都标结论，阻断项写清位置与替换建议。
5. **降级要显式**：接口不可用、质检未执行、字段被跳过，都必须在成品卡上写明，不许静默假装正常。
6. **热点只借结构**：不抄标题、不抄句子、不抄他人数据。

## 工作流程

| 阶段 | 名称 | 产出 | 确认门 |
|---|---|---|---|
| 零 | 意图与模式判定 | 意图、模式、分数、证据 | 分数 40–69 时二判；商单缺 brief 时追问 |
| 一 | Brief 解析（仅商单） | 营销事实卡 | 用户确认事实卡 |
| 二 | 画像与热点装配 | 装配摘要（≤200 字） | 无（异常时标注降级） |
| 三 | 三策略生成 | 3 版完整脚本 | 无 |
| 四 | 三层质检 | 每版结论 + 命中清单 | BLOCK 时修复，最多 3 轮 |
| 五 | 展示与成品卡 | 对话内 3 版 + Markdown 成品卡 | 用户选版或提修改 |
| 六 | 定点改写 | 新版本 + 版本链 | 每轮改完复检 |

## 阶段零：意图与模式判定

**先跑脚本，不要凭感觉判断。**

```bash
python3 scripts/intent_score.py --text "<用户原话>" [--attachment] [--in-flow] [--commercial]
```

输出 `intent`、`modality`、`platform`、`mode`、`score`、`layers`、`evidence`、`handoff`、`notes`。规则全文见 `references/intent-rubric.md`。

### 0.1 五条前置规则（命中即结束，不再打分）

| 顺序 | 条件 | 动作 |
|---|---|---|
| ① | 已在脚本链路中（等补字段／等选版／改写中） | `--in-flow`，直接续接；有改动动词 + 指代版本 → `rewrite` |
| ② | 显式拒绝（「不用写」「先不生成」） | 退出技能 |
| ③ | **形态判定** | `handoff_video`：识别为抖音／短视频／分镜／口播稿 → 读并转交 `paiya-xiaopai-douyin-video-generation`，不在本技能里硬写分镜。`confirm_modality`：图文与视频信号冲突、或只说「写个脚本」看不出形态 → 只问一次「要小红书图文笔记，还是视频脚本（抖音）？」，答完直接走对应分支，不再重复提问。小红书视频 → 说明本期视频分支只覆盖抖音，不静默改写 |
| ④ | 评估诉求（「帮我看看这篇」「为什么没流量」）且无创作动词 | 只出评估，不生成、不写版本链 |
| ⑤ | 方法论提问（怎么起号、违规词有哪些、几点发） | 按日常问答，不进入链路 |

**为什么形态要前置**：图文和视频的产出结构、锚点体系、质检判据完全不同。判错形态的代价远高于多问一句——给要视频的人塞三篇图文，等于整轮返工。

### 0.2 三层打分与阈值

| 层 | 内容 | 上限 |
|---|---|---|
| 第一层 | 硬信号：平台词 +20、创作动词 +20、产出对象 +15、brief 附件 +25、商单词 +20、数量结构 +10、产品实体 +10 | 65 |
| 第二层 | 关键词密度：创作动词族、内容要素词、平台词密度 | 30 |
| 第三层 | 扣分：方法论 −25、诊断 −20、寒暄 −40、只有平台词 −10 | — |

- **≥70**：直接触发，不要再问「是否需要写脚本」。
- **40–69**：调用 LLM 二判（`temperature=0`，只答是／否），判「是」才触发。
- **<40**：按日常问答回复；可在末尾补一句「需要的话我可以帮你写成小红书笔记」。
- **例外**：带 brief 的商单请求落在 40–69 时直接触发，无需二判。

### 0.3 四种走向

| 走向 | 判定 | 处理 |
|---|---|---|
| **商单创作** | 有 brief 附件，或显式「商单／合作／brief／品牌方」 | 走阶段一解析 brief，再生成 |
| **日常创作** | 无 brief，用户要一篇笔记但无产品信息 | 跳过阶段一，只用画像 + 热点；不得写任何价格功效事实 |
| **日常聊天** | `chat` / `evaluate` | 退出技能，正常对话或出评估报告 |
| **视频分支** | `handoff_video` | 不在本技能内生成，转交 `paiya-xiaopai-douyin-video-generation` |
| **待确认** | `confirm_modality` | 只问一次图文还是视频，答完立即路由 |

**商单但无 brief**：要求上传或贴文字，给最少信息清单（产品是什么、卖点 1–3 条、卖给谁、有无价格活动）。**不得**自行编一个产品，也**不得**静默降级成日常模式。

## 阶段一：Brief 解析（仅商单）

完整规则与字段表见 `references/brief-extraction.md`。

1. **读取**：PDF 用 `pdf` Skill，Word 用 `word` Skill，Excel/CSV 用 `sheet` Skill，PPT 用 `ppt` Skill，图片先 OCR，纯文本直接读。链接先判域名再选工具。
2. **抽字段**：品牌、产品、品类、核心卖点（1–3）、目标人群为必填；价格机制、规格成分、场景、竞品禁区、内容要求为选填。每个字段保留原文片段。
3. **出事实卡**：用表格展示，字段 + 值 + 原文片段。字段结构参照 `references/mock/mock-fact-card.json`。
4. **确认门**：事实卡必须经用户确认后才能生成。用户改哪个字段就只更新哪个，不重跑整份解析。
5. **缺失处理**：必填项缺失时一次性最多问 3 项，允许跳过；跳过字段进入写作禁令（不写价格／成分／认证／人群）。
6. **完全无信息**：直接请用户上传 brief 或贴文字，不生成任何内容。

POC 演练用 `references/mock/mock-brief.md`，解析结果应与 `mock-fact-card.json` 基本一致。

## 阶段二：画像与热点装配

```bash
python3 scripts/fetch_context.py --compact          # 装配摘要
python3 scripts/fetch_context.py                    # 完整 JSON
python3 scripts/fetch_context.py --fail profile     # 模拟画像接口失败
```

1. **画像**：只取 `whitelist_fields_used` 中的字段（赛道、人设、语气、人群需求、价格敏感度、爆款结构、商业规则）。**不把粉丝数、单篇数据写进脚本**，只用于选策略与定语气。
2. **热点**：取 3–4 篇笔记 + 1–2 条视频的结构拆解，只允许借用结构与选题角度，禁止复用标题原句与具体数据（见 `mock-trends.json` 的 `usage_rules`）。
3. **装配摘要**：写成 ≤200 字的一段，包含赛道关键词、人群痛点、可用结构、要避开的饱和选题。
4. **降级**：画像失败 → 用 brief 自带人群，标注「本次未使用画像」；热点失败 → 标注「无热点参考，按通用结构生成」。降级不阻断流程，但必须写进成品卡。

## 阶段三：三策略生成

结构、长度、锚点规则见 `references/script-schema.md`。

三版分别按以下策略生成，**必须并发生成、互不参照**：

| 版本 | 策略 | 一句话骨架 |
|---|---|---|
| V1 | 痛点共鸣 | 痛点自述 → 代价具体化 → 试错 → 产品出场 → 感受 → 提问式 CTA |
| V2 | 场景种草 | 场景切入 → 五感细节 → 产品作道具 → 动作拆解 → 状态变化 → 互动 CTA |
| V3 | 测评对比 | 结论前置 → 三个维度 → 逐项对比 → 算账 → 适用/不适用 → 选择式 CTA |

硬约束（生成后自检，违反只重写冲突部分）：

- 三版标题无 ≥6 字连续相同；三版 B1 首句无 ≥8 字连续相同。
- 同一开场句式只能出现一次；三版骨架不得重合。
- 每版覆盖 ≥2 个核心卖点，且主推卖点不完全相同。
- 正文 350–700 字，单段 ≤120 字，硬上限 1000 字；标题 ≤20 字。

## 阶段四：三层质检

```bash
python3 scripts/qc_check.py --file <成品卡.md> --version V1    # 逐版质检（推荐）
python3 scripts/qc_check.py --file <成品卡.md> --version V1 --daily   # 日常创作（无 brief）
python3 scripts/qc_check.py --text "<单版正文>"                # 单段或单版文本
python3 scripts/qc_check.py --file <文件> --brief references/mock/mock-fact-card.json
```

**必须逐版跑**，不要拿整份成品卡一次跑：元信息里的日期、红人 ID、字数统计会被误当成事实数字。

**日常创作没有 brief**，必须加 `--daily`：跳过卖点覆盖与事实对照，只跑规则层 + 结构层，否则会被误判成「核心卖点缺失」。

| 层 | 查什么 | 执行方式 |
|---|---|---|
| 规则层 | 绝对化、功效宣称、站外引流、违规暗示 | 脚本自动，命中即 BLOCK |
| 语义层 | 夸大、贬低、虚假对比、恐吓 | 模型逐段判断，命中记 WARN |
| 覆盖层 | 卖点 ≥2、事实与 brief 一致、人群指向、结构完整、brief 禁用项 | 脚本自动 + 人工核对数字待核项 |

处理规则：

- **BLOCK**：只改命中处，其余逐字不动，复检最多 3 轮；3 轮仍 BLOCK 则停止自动修复，提示换策略或人工介入，该版标「草稿·未通过质检」。
- **WARN**：可交付，展示时附建议清单。
- **质检未执行**（脚本报错、词表缺失）：全部降级为草稿，成品卡不得写「已质检」，只能写「质检范围：…」。
- 数字待核项（`numbers.candidates`）由模型对照事实卡逐个人工判断：来自 brief 则放行，属于编造则改掉。

## 阶段五：展示与成品卡

### 5.1 对话内展示

按 V1 → V2 → V3 顺序逐版展示，每版固定字段：定位、标题（含 2 个备选）、封面、正文（B1–B6 带锚点）、标签、配图建议、质检结论。最后给 3 行比选建议：哪版适合曝光、哪版适合收藏、哪版适合转化。

### 5.2 Markdown 成品卡

写入当前项目目录，文件名 `小红书脚本_<产品名或主题>_<YYYYMMDD>.md`。必须包含：

1. 元信息：生成时间、模式、红人 ID、产品、交付要求
2. 上下文装配摘要 + 降级标注
3. 三版脚本全文（带锚点）
4. 质检报告表（每条命中带位置、原文、建议替换）
5. 版本链（初稿 → 每次改写）
6. 依据链：brief 来源与版本、画像调用摘要、热点调用摘要、质检范围
7. 待补充项（`【待补充】` 汇总）

成品卡是交付物，不是草稿箱；不得出现「已质检」但实际未跑的表述。

## 阶段六：定点改写

用户说法到锚点的映射、改写铁律见 `references/script-schema.md` 第 2 节。

1. **定位**：解析版本号（V1/V2/V3 或「第一版／第二个」）、区块（T/C/B1–B6/H/P）、范围（局部／全局语气）。
2. **定位不清只问一次**：给候选（「改 V1 的标题，还是整篇语气？」），回答后立即执行。
3. **执行**：只重生成被点名的锚点，其余逐字不变；形成新版本（V1 → V1.1），旧版保留可回退。
4. **复检**：改写后规则层必跑；命中就再修，不超过 3 轮。
5. **回写**：更新成品卡的版本链与对应版本全文，不删旧版。
6. **不满意**：只重生成该版，其他两版保留可切回。

## 降级与异常

| 场景 | 处理 |
|---|---|
| 画像接口超时 | 用 brief 人群替代，标注「本次未使用画像」，流程继续 |
| 热点接口超时／为空 | 标注「无热点参考」，按通用结构生成 |
| brief 解析失败（加密／模糊） | 说明原因，请用户换格式或贴文字，不猜内容 |
| brief 有多个产品 | 列出清单请用户指定，不混写 |
| 三版出现同质化 | 只重写冲突版，另两版不动 |
| 质检脚本不可用 | 全部标草稿，成品卡写明质检范围 |
| 用户中途改方向 | 回到对应阶段，保留已有版本，不整链重跑 |
| 用户要求抖音／视频 | 转交 `paiya-xiaopai-douyin-video-generation`；小红书视频则说明本期视频只覆盖抖音，不冒充已支持 |
