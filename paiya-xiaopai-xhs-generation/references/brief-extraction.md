# Brief 解析规范（商单模式）

商单模式的第一道关口。目标是把任意格式的产品资料，折成一张结构固定、可核对的「营销事实卡」。解析失败或字段缺失时，宁可追问，不允许编造。

## 目录

1. 支持的输入类型
2. 营销事实卡字段表
3. 解析流程
4. 缺失判定与追问
5. 冲突与异常处理
6. 事实卡示例

## 1. 支持的输入类型

| 输入类型 | 读取方式 | 注意 |
|---|---|---|
| PDF | `pdf` Skill | 扫描件需先做 OCR，表格优先保留结构 |
| Word（.docx） | `word` Skill | 保留表格与项目符号 |
| Excel / CSV（.xlsx/.csv） | `sheet` Skill | 多 sheet 时先列 sheet 名再读 |
| PPT（.pptx） | `ppt` Skill | 按页读取，卖点常在单页大字 |
| 纯文本 / Markdown | 直接读取 | 最常见，按标题层级切分 |
| 图片（brief 截图） | 图像识别 + OCR | 识别后需回读关键数字确认 |
| 文档链接（飞书/腾讯/语雀） | 对应平台 Skill | 先判域名再选读取方式，不得混用 |

读取顺序：先取正文，再取表格，最后取图片文字。三类内容都要过，卖点经常只出现在表格或图片里。

## 2. 营销事实卡字段表

| 字段 | 必填 | 说明 | 缺失后果 |
|---|---|---|---|
| `brand` 品牌 | 是 | 品牌名，可含英文 | 无法定位主语，必须问 |
| `product` 产品名 | 是 | 具体到单品，不接受「他家的东西」 | 必须问 |
| `category` 品类 | 是 | 食品 / 饮品 / 零食 / 调味 等 | 影响合规口径，必须问 |
| `selling_points` 核心卖点 | 是 | 1–3 条，按优先级排序 | 无卖点则无内容可写，必须问 |
| `audience` 目标人群 | 是 | 年龄、城市、身份、需求 | 缺失则用画像人群替代，并在成品卡标注 |
| `price` 价格与机制 | 否 | 日常价、活动价、赠品、时间窗 | 缺失则全篇不得写价格 |
| `spec` 规格与成分 | 否 | 净含量、配料、工艺、保质期 | 缺失则不得写成分与工艺 |
| `scenes` 使用场景 | 否 | 具体到时间地点 | 缺失则从画像的场景词补 |
| `competitor` 竞品与禁区 | 否 | 不得提及的品牌、不得对比的维度 | 缺失则默认不做点名对比 |
| `goal` 传播目标 | 否 | 曝光 / 种草 / 转化 | 缺失默认种草 |
| `content_rules` 内容要求 | 否 | 必须出现、建议出现、禁用表达 | 缺失则只套用平台通用规则 |
| `deliverable` 交付要求 | 否 | 篇数、平台、形式、发布窗口 | 缺失默认 3 版小红书图文 |

**「必填」的含义**：不是硬性阻断，而是「缺失后必须追问一次」。用户明确跳过时，按第 4 节的降级规则执行。

## 3. 解析流程

1. **切分结构**：按标题、表格、列表切块，标记每块的来源位置（页码 / sheet 名 / 段落号）。
2. **抽字段**：逐字段在切块中查找，命中即记录原文片段；一个字段可能命中多处，全部保留。
3. **归一化**：价格统一成「数字 + 单位 + 适用时间」，成分统一成列表，人群拆成「年龄 / 城市 / 身份 / 需求」四元组。
4. **自检**：必填字段是否齐全、数值是否互相矛盾、是否有 brief 未提及但需要写的内容。
5. **出卡**：输出事实卡，每个字段附「原文片段」，让用户能核对来源。

事实卡不是给机器看的 JSON 就完事，要能在对话里展示成一张可读的表。

## 4. 缺失判定与追问

### 4.1 完全没有任何产品信息

用户说「帮我写个商单」但既没附件也没产品描述：

> 商单模式需要产品信息才能写。你可以直接上传品牌 brief（PDF / Word / Excel / PPT 都行），也可以贴一段文字，告诉我这几件事就够了：**产品是什么、核心卖点 1–3 条、卖给谁、有没有价格或活动**。

**不得**自行编造一个产品先写出来。也**不得**直接切到日常模式——那会让用户以为商单流程能绕过 brief。

### 4.2 必填字段部分缺失

一次性最多问 3 项，按影响排序（卖点 > 人群 > 产品名 > 品类）。追问时给出「可不答」的出口：

> brief 里没看到「核心卖点」和「目标人群」。方便补一句吗？如果暂时没有，我可以先按品类通用卖点写，但价格和功效类内容一律不写。

用户跳过 → 记录 `skipped_fields`，进入 4.3 的禁令。

### 4.3 跳过后的写作禁令

| 跳过的字段 | 写作禁令 |
|---|---|
| 价格 | 全篇不出现任何金额、折扣、赠品、限时信息 |
| 成分 / 工艺 | 不写配料表、不写工艺名词、不写「0 添加」类表述 |
| 认证 / 检测 | 不写任何认证、检测、报告、评分 |
| 人群 | 用画像人群替代，成品卡标注「人群来自画像，非 brief」 |

禁令在质检的「覆盖层」会被逐条校验，违反即阻断。

## 5. 冲突与异常处理

| 情况 | 处理 |
|---|---|
| brief 内价格前后不一致 | 不自行选一个。列出两个数字与出处，问用户以哪个为准 |
| 卖点与禁用表达冲突（如 brief 要求写「最」） | 以平台合规优先，告知用户该表述不能写，并给替代表述 |
| 附件无法解析（加密、损坏、纯图片且模糊） | 说明解析失败的原因，请用户换格式或贴文字，不猜内容 |
| 附件里有多个产品 | 列出产品清单，请用户指定本次要写哪一个，不混写 |
| brief 是竞品资料 | 提示这是竞品 brief，确认是否仍要继续 |

## 6. 事实卡示例

以 `mock/mock-brief.md` 为例，解析结果应如下（节选）：

| 字段 | 值 | 原文片段 |
|---|---|---|
| 品牌 | 山栖 SHANQI | 「品牌：山栖 SHANQI」 |
| 产品 | 冷萃咖啡液（原味） | 「产品：冷萃咖啡液（原味）」 |
| 品类 | 食品 / 咖啡饮品 | 「品类：食品 / 咖啡饮品」 |
| 核心卖点 | ①0 糖 0 脂 ②6.9 元/条 ③3 秒速溶 | 「1. 0 糖 0 脂…」「2. 单条成本 6.9 元…」 |
| 目标人群 | 22–30 岁一二线打工人、减脂期人群 | 「22-30 岁一二线城市打工人…」 |
| 价格机制 | 日常 99 元 / 活动 69 元（11.20–11.30）/ 买 2 盒送杯 | 「日常价：99 元 / 盒…」 |
| 规格成分 | 30ml×10 条；0 蔗糖 0 脂肪；云南日晒豆；12 小时冷萃；80mg 咖啡因 | 「规格：30ml × 10 条 / 盒…」 |
| 场景 | 早八 / 办公室下午 / 健身后 / 露营 / 加班 | 「六、可用场景」 |
| 内容要求 | 必现 3 条卖点；禁绝对化、禁功效、禁站外引流、禁贬低竞品 | 「七、内容要求」 |
| 交付 | 3 版小红书图文，报备笔记 | 「合作形式：小红书图文笔记…」 |

事实卡确认后才进入生成。用户改哪个字段，就只更新那个字段，不重跑整份解析。
