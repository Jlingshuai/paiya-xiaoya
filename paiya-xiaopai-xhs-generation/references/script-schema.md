# 脚本结构与锚点规范

本文件定义 3 版脚本的输出结构、锚点命名、三套策略的骨架差异，以及版本间互斥的硬约束。所有生成与改写都必须遵守，否则多轮改写无法定点。

## 目录

1. 单版输出结构
2. 锚点命名与改写定位
3. 三套策略骨架
4. 互斥硬约束
5. 长度与格式限制
6. 事实使用边界
7. 版本链与留档

## 1. 单版输出结构

每一版必须按以下字段输出，顺序固定：

```markdown
### V1｜痛点共鸣

- **定位**：一句话说明这版打给谁、靠什么钩子（≤40 字）
- **标题**：T1 主标题（≤20 字）；备选 T2、T3
- **封面**：C 大字（≤8 字）+ 副标（≤14 字）
- **正文**：
  - B1 钩子（≤60 字）
  - B2 场景/痛点（≤120 字）
  - B3 产品出场（≤120 字）
  - B4 细节或证据（≤120 字）
  - B5 结论（≤80 字）
  - B6 CTA（≤50 字）
- **标签**：H，5–8 个，含赛道、人群、场景各至少 1 个
- **配图**：P1–P3~6，每张一句画面描述，P1 固定为封面图
- **事实引用**：本版用到的 brief 字段清单，便于质检核对
```

正文段落数量固定为 6 段，便于锚点稳定。某段内容确实很短时可以合并语义，但**不得删除锚点**，改为在该锚点下写一句话。

## 2. 锚点命名与改写定位

锚点格式：`V{版本号}-{区块}{序号}`

| 锚点 | 指向 | 示例 |
|---|---|---|
| `V1-T` | 标题组（含 T1/T2/T3） | `V2-T` |
| `V1-C` | 封面文案 | `V3-C` |
| `V1-B1` … `V1-B6` | 正文第 1–6 段 | `V2-B3` |
| `V1-H` | 话题标签组 | `V1-H` |
| `V1-P1` … `V1-P6` | 配图描述 | `V2-P1` |

用户说法到锚点的映射：

| 用户说法 | 解析结果 | 重生成范围 |
|---|---|---|
| 「改第一个标题」 | `V1-T` | 只重出 T1/T2/T3，正文逐字不动 |
| 「第二个语气太硬」 | `V2` 全局语气 | 全篇改语气，结构、事实、锚点不动 |
| 「第三版第 2 段太长了」 | `V3-B2` | 只改 B2，按长度约束压缩 |
| 「换个开头」 | 当前选中版 `-B1` | 只改 B1，B2–B6 不动 |
| 「把卖点提前」 | 当前选中版 `-B3` 与 `-B4` | 两段顺序或合并调整，其余不动 |
| 「标签再加两个」 | `-H` | 只补标签，正文不动 |
| 「整体重写」 | 整版 | 重新走策略生成，旧版保留 |

**定位不清时只问一次**：给出候选锚点（如「你是想改 V1 的标题，还是整篇语气？」），用户回答后立即执行，不反复追问。

**改写铁律**：除被点名的锚点外，其余内容必须逐字不变。用户要能一眼看出「只改了那一处」。

## 3. 三套策略骨架

三版必须走不同说服路径，不允许只是同一篇的三个措辞版本。

### V1 痛点共鸣

| 锚点 | 内容要求 |
|---|---|
| B1 | 第一人称痛点自述，带具体时间或场景（如「7:40 站在地铁口」） |
| B2 | 把代价具体化：一个月多少钱、每天浪费多少时间、状态差到什么程度 |
| B3 | 试错经历：之前用什么、为什么不行（不贬低具体品牌） |
| B4 | 产品出场：一条硬事实 + 一个使用动作 |
| B5 | 结果感受：主观、可验证，不承诺功效 |
| B6 | 提问式 CTA（「你们一个月咖啡预算多少」） |

### V2 场景种草

| 锚点 | 内容要求 |
|---|---|
| B1 | 场景切入：时间 + 地点 + 正在做的事 |
| B2 | 五感细节：看到的、闻到的、喝到的、手上的触感 |
| B3 | 产品作为场景道具自然出现，不做功能罗列 |
| B4 | 使用动作拆成 2–3 步，每步一句 |
| B5 | 状态变化：喝完/用完之后的感受 |
| B6 | 互动式 CTA（「你们下午几点最困」） |

### V3 测评对比

| 锚点 | 内容要求 |
|---|---|
| B1 | 结论前置：推荐什么、不推荐什么，各一句 |
| B2 | 声明 3 个对比维度（如单次成本 / 便利性 / 成分） |
| B3 | 逐项对比：每项一句事实 + 一句判断 |
| B4 | 算账：把单价换算成「每次成本」，与门店或同类对比 |
| B5 | 适用与不适用人群各说一句，主动劝退一部分人 |
| B6 | 选择式 CTA（「按你的情况选」） |

## 4. 互斥硬约束

生成后必须自检，任一条不满足就只重写冲突部分：

1. **标题不得雷同**：三版 T1 之间不允许出现 ≥6 个连续相同汉字。
2. **开头不得雷同**：三版 B1 首句之间不允许出现 ≥8 个连续相同汉字。
3. **句式不得复用**：同一口头禅或开场句式（「作为一个…」「说实话…」「姐妹们…」）在 3 版中只能出现 1 次。
4. **骨架不得重合**：三版的段落推进顺序必须分别符合第 3 节三张表，不允许三版都用「痛点 → 产品 → CTA」。
5. **卖点组合要有差异**：三版各自至少覆盖 2 个核心卖点，且主推卖点不完全相同。

## 5. 长度与格式限制

| 项 | 限制 |
|---|---|
| 标题 | ≤20 字（平台上限），建议 12–18 字 |
| 封面大字 | ≤8 字，必须能独立成句 |
| 单段正文 | ≤120 字 |
| 整篇正文 | 350–700 字，硬上限 1000 字 |
| 标签 | 5–8 个，赛道 / 人群 / 场景各 ≥1 |
| 配图 | 3–6 张，P1 为封面图 |
| 表情符号 | 可选，每版 ≤6 个，不得替代文字信息 |

## 6. 事实使用边界

| 类型 | 规则 |
|---|---|
| 价格、规格、成分、工艺、时效、认证 | 只能来自 brief 原文，且必须与 brief 一致 |
| brief 未提供的事实 | 不写。确有必要时写 `【待补充：xxx】` 交给用户补 |
| 主观感受 | 可以写（「我觉得顺口」「我个人更喜欢」），但不得写成检测结论 |
| 检测数据、实验结论 | 不得虚构。brief 没给就不写「实测 0 卡」「测评 98 分」 |
| 竞品 | 可做维度对比，不得点名贬低，不得编造竞品缺陷 |
| 功效 | 食品不得宣称减肥、燃脂、治疗、提神醒脑等功效，即使 brief 写了也要拦 |

**热点参考的边界**：只允许借用结构与选题角度，禁止复用原标题、原句、原文段落、具体互动数据与他人个人信息（详见 `mock/mock-trends.json` 的 `usage_rules`）。

## 7. 版本链与留档

每次改写形成一个新版本，保留旧版：

```text
V1（初稿）→ V1.1（改标题：把「早八人」换成「7:40 的地铁」）→ V1.2（B3 缩短 30 字）
```

版本链需记录：

- 触发改写的用户原话
- 命中的锚点
- 改动摘要（改了什么、没改什么）
- 改写后质检结论

成品卡必须包含版本链，便于回溯「哪一版因为什么被改」。
