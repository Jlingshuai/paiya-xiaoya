# 意图识别与打分规则（POC 版）

本文件定义「一条用户输入是否应该启动小红书脚本生成链路」，以及启动后走哪种模式。规则参考 `paiya-report-scheduler` 的三层递进判定，但信号词表、权重和阈值按脚本创作场景重新设计。

## 目录

1. 判定顺序（先规则、后打分）
2. 四类意图的定义
3. 三层打分表
4. 阈值与决策
5. 第三层 LLM 二判
6. 正负例（含实测分数）
7. 校准方法

## 1. 判定顺序

按以下顺序执行，前一步命中即结束，不进入后续打分：

| 顺序 | 判定 | 命中条件 | 结果 |
|---|---|---|---|
| ① | 流程续接 | 当前会话已处于脚本链路（等补字段 / 等选版 / 改写中 / 等确认） | 直接续接，`intent=continue`，跳过打分 |
| ② | 显式拒绝 | 「不用写」「先不生成」「算了」 | 退出技能，`intent=exit` |
| ③ | 形态路由 | 出现视频信号（抖音 / 视频脚本 / 短视频 / 分镜 / 口播稿 / 镜头 / 竖屏），或平台与形态说不清 | `intent=handoff_video` 转交抖音视频技能；`intent=confirm_modality` 只问一次图文还是视频 |
| ④ | 评估诉求 | 出现诊断词（帮我看看 / 分析 / 诊断 / 复盘 / 为什么没流量），且无创作动词 | `intent=evaluate`，只做评估不生成 |
| ⑤ | 方法论提问 | 出现规则词（怎么起号 / 怎么涨粉 / 违规词有哪些 / 几点发 / 限流怎么办） | `intent=chat`，按日常问答处理 |
| ⑥ | 打分判定 | 以上均未命中 | 进入第 3 节三层打分，按第 4 节阈值决策 |

**为什么把评估和方法论前置**：这两类输入里常带「小红书」「笔记」等平台词，打分很容易过线。但它们的误触发代价最高——把「这篇为什么没流量」判成生成请求，会直接给用户塞一份新脚本，答非所问。

**为什么形态放在打分之前**：图文和视频的产出结构、锚点、质检判据完全不同。先判形态，再决定用哪套打分与流程；否则一个「抖音口播稿」会按图文的分值体系被误放进图文链路。

## 2. 四类意图与三种形态

| 意图 | 定义 | 典型说法 | 后续动作 |
|---|---|---|---|
| `generate` | 从零产出一篇或多篇小红书图文笔记脚本 | 「写 3 篇小红书笔记」「根据这个 brief 出三版」 | 进入阶段一（商单）或阶段二（日常） |
| `rewrite` | 对已生成的某一版做定点修改 | 「改第二个的标题」「第三段语气再轻一点」 | 进入阶段六（定点改写） |
| `evaluate` | 对已有内容做诊断、评分、优化建议，但不重写 | 「帮我看看这篇笔记怎么样」「这个脚本问题在哪」 | 输出评估报告，不写入版本链 |
| `chat` | 闲聊、方法论、平台规则、其他问答 | 「你好」「小红书怎么起号」「违规词有哪些」 | 退出技能，按日常问答回复 |

形态（`modality`）与意图正交，判定规则：

| 命中 | modality | platform | 结果 |
|---|---|---|---|
| 抖音 / douyin | `video` | 抖音 | `handoff_video` |
| 小红书 + 视频词（视频脚本 / 分镜 / 口播稿） | `video` | 小红书 | `handoff_video`，并告知本期视频只覆盖抖音 |
| 小红书 / 图文 / 笔记 / 封面 / 话题 | `article` | 小红书 | 走本技能 |
| 视频词 + 图文词同时出现、无平台 | `ambiguous` | — | `confirm_modality`，问一次 |
| 只有「脚本」等中性词 | `unspecified` | — | `confirm_modality`，问一次 |

**确认话术只有一句**：「要小红书图文笔记，还是视频脚本（抖音）？」用户答完立即路由，不追问第二遍。

模式（`mode`）与意图正交：

- `mode=商单`：存在产品 brief（附件或显式「商单 / brief / 品牌方」）→ 必须走阶段一解析 brief
- `mode=日常`：无 brief → 跳过 brief 解析，只用画像与热点

## 3. 三层打分表

### 第一层：硬信号（累加，封顶 65 分）

| 信号 ID | 命中条件 | 分值 |
|---|---|---|
| `L1.platform` | 出现平台词：小红书 / 红书 / xhs / 图文笔记 / 种草文 | +20 |
| `L1.action` | 出现创作动词：写 / 生成 / 出 / 来一篇 / 做一篇 / 改 / 润色 / 扩写 / 重写 | +20 |
| `L1.object` | 出现产出对象词：笔记 / 脚本 / 文案 / 标题正文 / 三版 / 版本 | +15 |
| `L1.brief` | 有产品资料附件（PDF / PPT / Word / Excel / CSV / TXT / MD / 图片） | +25 |
| `L1.commercial` | 出现商单词：商单 / 合作 / 推广 / 报备 / brief / 品牌方 / 甲方 | +20 |
| `L1.spec` | 出现数量或结构要求：3 版 / 三个版本 / 带话题 / 带标签 / 标题加正文 | +10 |
| `L1.entity` | 命中已知品牌或产品实体（来自 brief 或用户明确说出的产品名） | +10 |

**封顶 65**：避免单条输入靠堆词冲过阈值。

### 第二层：关键词密度加权（累加，封顶 30 分）

| 信号 | 计算方式 | 封顶 |
|---|---|---|
| 创作动词族 | 每命中 1 个不同动词 +8 | 16 |
| 内容要素词（卖点 / 人群 / 场景 / 成分 / 价格 / 测评 / 开箱 / 口感 / 性价比 / 转化） | 每满 2 个不同词 +3 | 9 |
| 平台词密度（小红书 / 红书 / xhs / 图文 / 笔记 / 封面 / 话题 / 标签） | 不同词 ≥ 2 个 +5 | 5 |

### 第三层：扣分项（累加，总分不低于 0）

| 扣分 ID | 命中条件 | 分值 |
|---|---|---|
| `P.method` | 方法论 / 规则提问（怎么起号 / 怎么涨粉 / 违规词有哪些 / 几点发 / 限流怎么办） | −25 |
| `P.evaluate` | 诊断诉求（帮我看看 / 分析 / 诊断 / 复盘 / 为什么没流量） | −20 |
| `P.chat` | 寒暄或闲聊（你好 / 在吗 / 谢谢 / 今天天气 / 随便聊聊） | −40 |
| `P.weak` | 只有平台词，没有任何产出对象或创作动词 | −10 |

**总分** = 第一层（≤65）+ 第二层（≤30）− 扣分，取值区间 0–95。

## 4. 阈值与决策

| 总分 | 决策 | 行为 |
|---|---|---|
| **≥ 70** | 触发 | 直接进入生成链路，不再追问「是否要写脚本」 |
| **40–69** | 待判 | 进入第三层 LLM 二判；判「是」则触发，判「否」按日常问答 |
| **< 40** | 不触发 | 按日常问答处理，可在回复末尾给一句「需要的话我可以帮你写成小红书笔记」 |

**阈值为什么是 70 而不是 60**：两条路的误判代价不对称。闲聊被判成脚本，用户会被硬塞进七步流程，打断体验且难恢复；脚本需求被判成闲聊，用户补一句「帮我写」即可恢复。所以脚本方向的入路门槛必须从严，宁可多问一句。

**例外**：`mode=商单` 且 `L1.brief` 命中时，即使总分落在 40–69，也直接触发——用户已经上传了产品资料，意图几乎没有歧义。

## 5. 第三层 LLM 二判

仅在总分 40–69 时调用，要求 `temperature=0`，只输出一个词。

```text
你是意图分类器。判断下面这句话是否在要求「生成或改写一篇小红书图文笔记脚本」。
只回答「是」或「否」，不要解释。

用户输入：{utterance}
是否带有产品资料附件：{has_attachment}

是 = 用户想要一篇可直接使用的小红书笔记内容（标题、正文、标签）
否 = 用户在问方法、问规则、聊天、评估已有内容，或在说别的事
```

二判返回「是」→ `intent=generate`；返回「否」→ `intent=chat`，不进入链路。

## 6. 正负例（含实测分数）

以下分数由 `scripts/intent_score.py` 实跑得出，可作为回归测试基线。修改权重后必须重跑本表。

| # | 输入 | 附件 | 分数 | 判定 | 理由 |
|---|---|---|---|---|---|
| 1 | 帮我写3篇小红书笔记，种草这个咖啡液 | 无 | 78 | generate / 日常 | 平台+动作+对象+数量+实体五类硬信号齐全，封顶 65 |
| 2 | 按这个 brief 写三版小红书脚本 | 有 | 73 | generate / 商单 | 附件 + 商单词 + 数量要求 |
| 3 | 帮我改一下第一版的标题 | 无 | 43 | rewrite（仅在链路中） | 会话已有版本时，`in_flow` 前置规则直接判改写 |
| 4 | 小红书违规词有哪些 | 无 | 0 | chat | 方法论扣分 −25 覆盖平台词 +20 |
| 5 | 帮我看看这篇笔记为什么没流量 | 无 | 0 | evaluate | 诊断词前置，无创作动词 |
| 6 | 你好，在吗 | 无 | 0 | chat | 纯寒暄，扣 40 后归零 |
| 7 | 生成3个抖音视频脚本 | 无 | 43 | handoff_video | 分数进入二判区间，但形态为视频，转交视频技能 |
| 8 | 这个产品怎么在小红书上推广 | 无 | 30 | chat | 有平台词与推广词，但无产出对象，扣 `P.weak` |
| 9 | 帮我写一篇小红书 | 无 | 48 | 二判 | 有平台、动作、对象，缺产品与数量，需确认一次 |
| 10 | 今天天气不错 | 无 | 0 | chat | 无关输入 |
| 11 | 帮我写篇脚本 | 无 | 43 | confirm_modality | 只有「脚本」，看不出图文还是视频，问一次 |
| 12 | 按这个 brief 出三条口播稿 | 有 | 45 | handoff_video | 口播稿属视频形态，附件不改变形态判定 |

> 第 3 条必须带 `--in-flow` 才判 rewrite；不带该标记时是 43 分、进入二判。第 8 条曾是 `llm_check`，实测发现「推广咨询」更接近日常问答，故把期望值改为 `chat`，并在规则里保留 `P.weak` 扣分。

## 7. 校准方法

1. 收集 30–50 条真实用户输入，人工标注 `generate / rewrite / evaluate / chat`。
2. 跑 `python3 scripts/intent_score.py --eval references/intent-cases.jsonl`，输出混淆矩阵。
3. 关注两个指标：脚本类**查全率**（漏判）优先于查准率（误判），漏判会让用户觉得「听不懂话」。
4. 调整顺序：先调扣分项（误判主要来自评估与方法论），再调第一层权重，最后才动阈值。
5. 每次调整后必须更新第 6 节基线表，否则回归无据可依。
