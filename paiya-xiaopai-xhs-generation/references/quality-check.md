# 质检规范（三层校验）

质检决定一版脚本能否作为「成品」交付。规则层查词，语义层查意思，覆盖层查事实与卖点。三层都过才算通过。

## 目录

1. 三层职责
2. 规则层：词表与判定
3. 语义层：四类问题
4. 覆盖层：五项核对
5. 结论等级与处理
6. 质检报告格式
7. 质检不可用时的降级

---

## 1. 三层职责

| 层 | 查什么 | 判定方式 | 能否自动化 |
|---|---|---|---|
| 规则层 | 违禁词、绝对化用语、站外引流、功效宣称 | 词表匹配 + 正则 | 是，`scripts/qc_check.py` |
| 语义层 | 夸大、贬低、虚假对比、恐吓 | 逐段阅读理解 | 否，模型判断 |
| 覆盖层 | 卖点落地、事实越界、人群指向、结构完整、brief 禁用项 | 逐项核对 | 大部分可自动 |

**顺序**：先跑规则层（快、确定），再跑覆盖层（可核对），最后跑语义层（慢、需要理解）。规则层有 BLOCK 时可以先修，不必等语义层。

---

## 2. 规则层：词表与判定

### 2.1 硬阻断词（命中即 BLOCK）

| 类别 | 词条 | 说明 |
|---|---|---|
| 绝对化用语 | 最好、最强、最低、最高、第一品牌、全网最低、史上最低、顶级、极致、唯一、永久、彻底、根治、100% 有效、绝对 | 平台明令禁止，无例外 |
| 功效宣称 | 治疗、治愈、疗效、防癌、抗癌、降血糖、降血压、降血脂、减肥、瘦身、燃脂、排毒、增强免疫力、抗衰老、提神醒脑 | 食品不得宣称功效，即使 brief 写了也要拦 |
| 金融承诺 | 稳赚、保本、零风险、无效退款 | 食品类基本不会出现，出现即异常 |
| 站外引流 | 加微信、加 V、vx、VX、私信我、私信领、淘宝搜、链接在评论区、主页有链接、代购、扫码加 | 小红书禁止导流站外 |
| 违规暗示 | 内部价、渠道价、员工价、绕过平台、私下交易 | 报备笔记尤其敏感 |

### 2.2 需人工确认（命中记 WARN，不阻断）

| 类别 | 触发 | 为什么只警告 |
|---|---|---|
| 评价性「最」 | 「最」+ 评价词（划算 / 值得 / 推荐 / 便宜 / 好吃 / 好喝 / 好用 / 好看 / 香 / 美 / 棒 / 佳 / 正宗 / 新鲜 / 适合） | 只盯评价性用法；「最后」「最近」「最里面」是正常词，不报警 |
| 百分比 | 出现「100%」「99%」 | 可能是成分占比等真实数据，需核对 brief |
| 数字承诺 | 「3 天」「一周」「立刻」等时效或效果词 | 需核对该说法是否有 brief 依据；来自 brief 的事实（如「12 小时冷萃」）自动跳过 |
| 程度副词 | 「超级」「巨」「爆炸」「绝了」 | 平台容忍度视语境，过度使用影响观感 |
| 竞品提及 | 出现其他品牌名 | 需确认无贬低、无虚假对比 |

### 2.3 替换建议库

| 原表述 | 建议替换 |
|---|---|
| 最好喝 / 最好用 | 我个人更常喝 / 目前最常用的是（不写「最」时可改「我回购次数最多」） |
| 全网最低 | 我对比到的价格里比较划算的 |
| 100% 有效 | 我自己的感受是明显（改为主观表述） |
| 立刻不困 | 喝完半小时后状态回来了（不承诺时效） |
| 减肥 / 瘦身 | 不写，改为「热量上更放心」 |
| 私信我 / 加微信 | 主页有整理 / 评论区聊 |
| 顶级原料 | 用的是云南日晒豆（写具体事实） |

## 3. 语义层：四类问题

逐段读，按下表判断：

| 问题 | 判定标准 | 例子 |
|---|---|---|
| 夸大 | 把主观感受写成客观结论，或无依据的程度断言 | 「喝完直接清醒一整天」 |
| 贬低 | 点名或暗示某类人/某品牌不行 | 「还在喝速溶的都是冤种」 |
| 虚假对比 | 做了对比但没给维度或数据 | 「比某品牌好喝十倍」 |
| 恐吓 | 用负面后果施压购买 | 「不喝你迟早垮掉」 |

语义层命中记 WARN；若同时命中规则层同类问题（如夸大 + 功效词），升级为 BLOCK。

## 4. 覆盖层：五项核对

| 项 | 要求 | 不满足的后果 |
|---|---|---|
| 卖点覆盖 | brief 的 3 条核心卖点中，至少有 2 条在正文自然出现（不是堆在标签里） | 少 1 条记 WARN；少 2 条记 BLOCK |
| 事实越界 | 价格、规格、成分、工艺、时效、认证必须与 brief 一致；brief 没给的一律不得出现 | 任一处不一致或凭空出现 → BLOCK |
| 人群指向 | 至少 1 处明确的目标人群或使用场景 | 缺失记 WARN |
| 结构完整 | T / C / B1–B6 / H / P 齐全，锚点不缺 | 缺关键区块 → BLOCK |
| brief 禁用项 | brief 的「禁止」清单逐条比对 | 命中 → BLOCK |

**卖点覆盖的判定**要严：只在标签里出现「0 糖 0 脂」不算覆盖，必须在正文有具体描述。

---

## 5. 结论等级与处理

| 等级 | 条件 | 展示 | 成品卡 |
|---|---|---|---|
| PASS | 0 BLOCK、0 事实越界、卖点 ≥2、结构完整 | 正常展示，标「已通过质检」 | 收录为成品 |
| WARN | 0 BLOCK，但有 WARN 项 | 正常展示，标「可交付，含 N 处建议」 | 收录，附建议清单 |
| BLOCK | 任一 BLOCK 项 | 展示但标「未通过，含阻断项」 | **不收录为成品**，标「草稿·未通过质检」 |

**修复循环**：

1. 命中 BLOCK → 只改命中处，其余逐字不动，形成新版本。
2. 复检，最多 3 轮。
3. 3 轮仍 BLOCK → 停止自动修复，提示用户「这一版卡在 {问题}，建议换策略或人工介入」，并把该版标为草稿。

**不得**为了通过质检而删掉 brief 要求的必现卖点——那会从「违规」变成「未履约」，同样不可交付。

## 6. 质检报告格式

```markdown
| 版本 | 策略 | 结论 | 规则层 | 语义层 | 覆盖层 |
|---|---|---|---|---|---|
| V1 | 痛点共鸣 | PASS | 0 命中 | 0 命中 | 卖点 3/3；越界 0；人群 ✓；结构 ✓ |
| V2 | 场景种草 | WARN | 1 命中（「最」需确认） | 0 命中 | 卖点 2/3；越界 0；人群 ✓；结构 ✓ |
| V3 | 测评对比 | BLOCK | 1 命中（「全网最低」） | 1 命中（贬低） | 卖点 2/3；越界 1（赠品数量缺失）；结构 ✓ |
```

每条命中要给出：**位置（锚点）+ 原文 + 问题类别 + 建议替换**。只给结论不给位置，用户没法改。

---

## 7. 质检不可用时的降级

- `qc_check.py` 执行失败（缺依赖、词表缺失）→ 规则层标记「未执行」，全部版本降级为「草稿」。
- 语义层模型不可用 → 语义层标记「未执行」，结论最高只能给 WARN。
- **任何一层未执行时，成品卡上不得出现「已质检」标识**，只能写「质检范围：规则层 + 覆盖层」。

宁可标注「没查」，也不能让用户以为查过了。
