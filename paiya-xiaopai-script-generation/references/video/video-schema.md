## 1. 单版脚本结构

每一版是一段可直接照着拍的表格，不是散文。固定顺序：

```markdown
### V1｜测评·结论前置（30 秒）

- **骨架**：dy_9d3f61ab｜6 段｜钩子 conclusion_first｜收尾 product_shot
- **定位**：给谁看、解决什么、为什么信
- **时长 / 比例**：30s（28–32s）｜9:16 竖屏
- **前 3 秒钩子**：具体写清画面 + 第一句台词
- **口播总字数**：xx 字（上限 150）
- **卖点落点**：S2 价格 / S4 成分 / S6 冲泡

| 镜号 | 时间码 | 时长 | 景别 | 画面 | 台词 / 口播 | 字幕 | 音效 / BGM | 转场 |
|---|---|---|---|---|---|---|---|---|
| S1 | 0-3s | 3s | 近景 | ... | ... | ... | ... | 硬切 |
| S2 | 3-6s | 3s | 特写 | ... | ... | ... | ... | 硬切 |

- **拍摄清单**：场景、道具、人员、光位
- **事实引用**：列出用到的 brief 事实与数字
```

缺任何一项都算结构不完整，质检会标 BLOCK。

## 2. 分镜表字段

| 字段 | 要求 | 常见错误 |
|---|---|---|
| 镜号 | `S1` 起连续编号，不跳号 | 出现 S0 或重复镜号 |
| 时间码 | `起-止s`，从 0 开始，与上一镜无缝 | 时间码重叠、留空档 |
| 时长 | `3s`，单镜 ≤5 秒 | 一镜写 8 秒（完播率杀手） |
| 景别 | 远景／全景／中景／近景／特写 | 写「正常」「随便」 |
| 画面 | 谁、在哪、做什么，可执行 | 写「氛围感」「高级感」 |
| 台词 / 口播 | 逐字可念，口语短句 | 书面长句、括号内心戏 |
| 字幕 | 与台词一致，或承担画面信息 | 字幕与台词两套说法 |
| 音效 / BGM | 曲库可用、环境音或音效 | 「热门 BGM」无具体指向 |
| 转场 | 硬切／叠化／甩镜等 | 每镜都写「炫酷转场」 |

## 3. 锚点体系

| 锚点 | 指代 | 改写粒度 |
|---|---|---|
| `V{n}-HOOK` | 前 3 秒钩子（画面 + 首句台词） | 换钩子类型 |
| `V{n}-COVER` | 标题 / 封面字 | 换标题、换封面文案 |
| `V{n}-S{k}` | 第 k 个镜头整行 | 换画面、换台词、换景别 |
| `V{n}-S{k}.line` | 该镜的台词单元格 | 只改口播 |
| `V{n}-S{k}.visual` | 该镜的画面单元格 | 只改画面 |
| `V{n}-CAP` | 全片字幕策略 | 改字幕风格或信息分工 |

锚点必须写进成品卡。用户说「第二个视频第 3 秒到第 5 秒」，先按时间码定位到具体镜号，再改那一行，不重写整段。

## 4. 用户说法 → 锚点映射

| 用户说法 | 实际要改的锚点 |
|---|---|
| 改第一个的标题 | `V1-COVER` |
| 开头再抓人一点 | `V1-HOOK`（只改 S1，不动 S2 之后） |
| 第 3 秒到第 5 秒人物表情丰富点 | 时间码落在哪一镜就改 `V{k}-S{n}.visual` |
| 第二个视频的口播太快 | 该版所有 `S{k}.line` 缩短，同步压字数 |
| 把价格提到前面 | 把价格句迁到更早的镜头，标注移动而非新增 |
| 换个 BGM | 该版「音效 / BGM」列整列替换 |
| 结尾再软一点 | 最后一镜台词与字幕 |

**定位不到**（例如「第 8 秒」落在空档、或用户说的版本不存在）→ 回问一句，不猜。

## 5. 骨架驱动：beat_roles → 镜号

三版 = M3 取到的 3 条视频骨架，按分数排 `V1 / V2 / V3`。骨架的 `beat_roles` 是**语义段**，一段不等于一个镜头；落到分镜表时按下面的规则拆镜。

| `beat_roles.role` | 拆成几镜 | 写法 |
|---|---|---|
| `hook` | 1–2 镜，总长 ≤3s | 按 `hook_type` 写：结论前置 / 提问 / 冲突 / 数字 / 场景代入 |
| `pain` | 1–2 镜 | 提需求、讲问题、锁人群、铺场景 |
| `product_in` | 2–3 镜 | 产品本体、包装、使用演示进入画面 |
| `proof` | 3–5 镜 | 实测、数据、资质、前后对比、口碑 |
| `ending` | 1–2 镜 | 按 `ending_type` 写：成品展示 / 效果对比 / 行动号召 / 首尾呼应 / 无收尾 |

硬规则：

1. **首段固定 hook、末段固定 ending**；中段顺序按骨架，不重排。
2. **段边界可拆不可并**：一个 beat 拆成多镜可以，多个 beat 合并成一镜不行（会丢职责）。
3. 单镜 ≤5s，总时长 28–32s，镜数 8–14；骨架 beats 只给顺序，秒数按本次 30s 重排。
4. `creator_req` 决定承载方式：`voiceover=0` 时口播压到 ≤10%，用字幕或画面承担信息；`demo_hands=1` 必须有手部特写。
5. `product_in` 不晚于 40% 时长（30s 档即 12s）。
6. `hook_sync` 只自检：首帧画面与首句口播是否同指一件事。

**形态 → 叙事形式**（用于给版本起名，不改变骨架职责）：

| `content_form` | 叙事形式 | 参考口播占比 |
|---|---|---|
| `review` | 真人口播测评 | 70% 以上 |
| `story` | 剧情演绎（冲突 / 误会） | 30–50% |
| `vlog` | 沉浸式跟拍 / 动作流 | ≤10%（可无口播） |
| `tutorial` | 教程演示（步骤 + 特写） | 40–70% |
| `list` | 清单口播（逐项点评） | 60–85% |

## 6. 降级骨架（无 M3 骨架时）

骨架接口不可用、或不足 3 条时，用以下三套固定叙事形式，并在成品卡标注「本次未使用爆款骨架」：

| 版本 | 叙事形式 | 口播占比 | 前 3 秒手法 | 适合的卖点 |
|---|---|---|---|---|
| V1 | 真人口播测评 | 70% 以上 | 直接抛数字或结论 | 价格、成分 |
| V2 | 剧情演绎（冲突 / 误会） | 30–50% | 第三方提问或冲突台词 | 场景、性价比 |
| V3 | 沉浸式跟拍 / 动作流 | ≤10%（可无口播） | 动作或声音先行 | 冲泡体验、质感 |

**每一版必须能单独成立**：不依赖另外两版做对比，用户只投一版也能跑。

---

## 7. 互斥硬约束

1. 三版前 3 秒钩子类型不得重复（数字／冲突／动作／提问只能各用一次），与三条骨架的 `hook_type` 对应。
2. 三版口播占比必须分档（>70% / 30–50% / ≤10%），不允许三版都是口播。
3. 同一开场句式的连续 6 字不得跨版重复。
4. 三版主推卖点不得完全相同：至少各自主推一条不同的卖点。
5. 三版结尾不得都是「价格 + 下单」；`ending_type` 至少两种。
6. 三版 `content_form` 尽量不同；骨架不足时允许两版同形态，但段序不得完全一致。

违反任一条，重写该版，不带病展示。

## 8. 时长与字数换算

| 时长 | 镜头数 | 口播上限（5 字/秒） | 建议实际字数（4.2 字/秒） |
|---|---|---|---|
| 15s | 5–8 | 75 | 60–65 |
| 30s | 8–14 | 150 | 120–135 |
| 60s | 15–22 | 300 | 240–270 |

- 单镜不超过 5 秒；超过就拆镜。
- 台词字数按去掉标点后计；字幕字数不计入口播上限，但单屏字幕不超过 18 字。
- 语速取自画像 `speech_features.speech_rate`（POC 为 4.2 字/秒），**镜头时长与台词字数必须匹配**：3 秒镜头配 20 字台词念不完，质检会拦。

---

## 9. 事实使用边界

- 价格、成分、工艺、咖啡因、限量数字只能来自 brief / 事实卡。
- brief 没写的认证、检测、获奖、销量，一律不写。
- 推算值必须可复算（如 69 ÷ 10 = 6.9 元/条），并在成品卡「数字人工判定」里写算式。
- 功效词一个都不能碰，包括「提神」这类看似中性的表述。

## 10. 版本链

```text
V1（初版·dy_9d3f61ab）→ V2（初版·dy_2a7c4f19）→ V3（初版·dy_8e41b076）
V2 → V2.1（改标题）
V2.1 → V2.2（改第 3–5 秒画面）
```

- 只记录被改过的版本，未改版不写链。
- 每轮改写后必须重跑该版质检，结论写进链尾。
