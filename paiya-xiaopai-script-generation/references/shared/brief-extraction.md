# Brief 解析（图文 / 视频共用）

商单模式的第一道关口：把任意格式的产品资料折成一张结构固定、可核对的「营销事实卡」。解析失败或字段缺失时，宁可追问，不允许编造。

## 目录

1. 支持的输入
2. 共用字段表
3. 分支特有字段
4. 解析流程
5. 缺失与追问
6. 冲突与异常
7. 事实卡结构（供质检脚本读取）

---

## 1. 支持的输入

| 输入 | 读取方式 |
|---|---|
| PDF | `pdf` Skill；扫描件先 OCR，表格优先保留结构 |
| Word / DOCX | `word` Skill；保留表格与项目符号 |
| Excel / CSV | `sheet` Skill；多 sheet 先列 sheet 名 |
| PPT | `ppt` Skill；按页读取，卖点常在大字页 |
| 纯文本 / Markdown / 聊天粘贴 | 直接读 |
| 图片 / 截图 | 图像识别 + OCR；关键数字逐字回读 |
| 飞书 / 腾讯 / 语雀 / 企业微信链接 | 先判域名，再选对应读取方式 |

读取顺序：正文 → 表格 → 图片文字。卖点经常只出现在表格或图片里，三类都要过。

---

## 2. 共用字段表

| 字段 | 必填 | 说明 | 缺失后果 |
|---|---|---|---|
| `brand` 品牌 | 是 | 品牌名，可含英文 | 必须问 |
| `product` 产品名 | 是 | 具体到单品，不接受「他家的东西」 | 必须问 |
| `category` 品类 | 是 | 食品 / 饮品 / 零食 / 调味 / 咖啡等 | 影响合规口径，必须问 |
| `selling_points` 核心卖点 | 是 | 1–3 条，按优先级排序 | 无卖点则无内容可写，必须问 |
| `audience` 目标人群 | 是 | 年龄、城市、身份、需求；缺失可用画像替代并标注 | 不阻断，但必须标注来源 |
| `price` 价格与机制 | 否 | 日常价、活动价、赠品、时间窗 | 缺失则全篇不得写价格 |
| `facts` 规格与成分 | 否 | 净含量、配料、工艺、保质期、咖啡因等 | 缺失则不得写成分与工艺 |
| `scenes` 使用场景 | 否 | 具体到时间地点 | 缺失则从画像补，标注来源 |
| `competitor` 竞品与禁区 | 否 | 不得提及的品牌、不得对比的维度 | 默认不做点名对比 |
| `content_rules` 内容要求 | 否 | 必须出现、建议出现、禁用表达 | 缺失则套用平台通用规则 |
| `forbidden_claims` 禁用宣称 | 否 | brief 明令禁止的说法 | 质检覆盖层逐条比对 |

**「必填」的含义**：不是硬性阻断，而是「缺失后必须追问一次」。用户明确跳过后，按第 5 节降级。

## 3. 分支特有字段

### 3.1 小红书图文

| 字段 | 默认 | 说明 |
|---|---|---|
| `deliverable.platform` | 小红书 | 平台 |
| `deliverable.format` | 图文笔记 | 产出形态 |
| `deliverable.versions` | 3 | 默认三版 |
| `deliverable.window` | — | 发布窗口 |
| 图文要求 | — | 标题字数、正文长度、标签数量、配图数量、报备要求 |

### 3.2 抖音视频

| 字段 | 默认 | 说明 |
|---|---|---|
| `video.duration_sec` | 30 | 15 / 30 / 60 秒档 |
| `video.ratio` | 9:16 | 竖屏 |
| `video.speaker` | 红人本人出镜口播 | 口播人 |
| `video.format` | 竖屏短视频，商单报备 | 挂车、报备、组件位置 |
| `video.shots_min` / `shots_max` | 8 / 14 | 30 秒档镜头数 |
| `video.max_shot_sec` | 5 | 单镜上限 |
| `video.oral_chars_per_sec` | 5 | 口播字数换算 |

**视频必抽**：时长、比例、口播人、是否挂车、是否报备。缺失时用默认值，并在事实卡标注「默认值，待确认」。

---

## 4. 解析流程

1. **通读一遍**，先标出所有数字与时间承诺（时长、活动期、限量、截止日）。
2. **抽字段**，每个字段保留原文片段（10–20 字），便于回溯。
3. **归一化**：价格统一成「数字 + 单位 + 适用时间」；成分统一成列表；人群拆成「年龄 / 城市 / 身份 / 需求」。
4. **判形态**：写清平台、图文还是视频、时长档、比例、是否口播、是否挂车。
5. **出事实卡**：表格展示，字段 / 值 / 原文片段 / 是否缺失。
6. **确认门**：用户确认后才生成；只改被点名字段，不重跑整份解析。

## 5. 缺失与追问

### 5.1 完全没有任何产品信息

> 商单模式需要产品信息才能写。你可以上传品牌 brief（PDF / Word / Excel / PPT 都行），也可以贴一段文字，告诉我：**产品是什么、核心卖点 1–3 条、卖给谁、有没有价格或活动**。

不得自行编一个产品，也不得静默降级成日常模式。

### 5.2 必填字段部分缺失

一次最多问 3 项，按影响排序（卖点 > 人群 > 产品名 > 品类）。给「可不答」的出口：

> brief 里没看到「核心卖点」和「目标人群」。方便补一句吗？如果暂时没有，我可以先按品类通用卖点写，但价格和功效类内容一律不写。

### 5.3 跳过后的写作禁令

| 跳过的字段 | 写作禁令 |
|---|---|
| 价格 | 不出现任何金额、折扣、赠品、限时信息 |
| 成分 / 工艺 | 不写配料表、不写工艺名词、不写「0 添加」类表述 |
| 认证 / 检测 | 不写任何认证、检测、报告、评分 |
| 人群 | 用画像人群替代，成品卡标注「人群来自画像，非 brief」 |

---

## 6. 冲突与异常

| 情况 | 处理 |
|---|---|
| brief 内价格前后不一致 | 不自行选一个；列出两个数字与出处，问用户以哪个为准 |
| 卖点与禁用表达冲突（如 brief 要求写「最」） | 平台合规优先，告知不能写，给替代表述 |
| 附件无法解析（加密、损坏、模糊） | 说明原因，请用户换格式或贴文字，不猜内容 |
| 附件里有多个产品 | 列出清单，请用户指定本次写哪一个，不混写 |
| brief 是竞品资料 | 提示这是竞品 brief，确认是否仍要继续 |
| brief 说 30s，用户说 15s | 以用户当轮为准，事实卡标注变更来源 |
| 价格与活动期不一致 | 以 brief 为准，提示用户核对 |

## 7. 事实卡结构（供质检脚本读取）

POC 用两份 MOCK 事实卡：

- 图文：`references/mock/xhs/mock-fact-card.json`
- 视频：`references/mock/video/mock-video-fact-card.json`

通用字段：

```json
{
  "brand": "品牌名",
  "product": "产品名",
  "entity_aliases": ["品牌简称", "产品简称"],
  "selling_points": ["卖点一", "卖点二", "卖点三"],
  "selling_point_keys": [["别名1", "别名2"], ["别名3"], ["别名4"]],
  "numbers_allowlist": [30, 10, 6.9, 69],
  "forbidden_claims": ["减肥", "提神醒脑"],
  "price_required": true,
  "price_tokens": ["69", "99"],
  "derived_numbers": [6.9]
}
```

视频额外字段：

```json
{
  "price_required": false,
  "price_policy_tokens": ["APP", "小程序", "当日售价"],
  "video": {
    "duration_sec": 30,
    "ratio": "9:16",
    "shots_min": 8,
    "shots_max": 14,
    "max_shot_sec": 5,
    "oral_chars_per_sec": 5,
    "hook_deadline_sec": 3
  }
}
```

**质检脚本不写死品牌与价格**：

- 产品名从 `entity_aliases` 读取；
- 价格从 `price_tokens` 读取；
- `price_required=false` 时，只要求最后两镜出现 `price_policy_tokens` 里的口径（如「APP 当日价」）；
- 可复算数字放 `derived_numbers`，不要硬编码在脚本里。
