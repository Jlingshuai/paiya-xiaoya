# 爆款骨架层：从骨架到达人（M3）

本文件对齐《M3-爆款骨架字段设计（图文 / 视频）》。骨架不是特征清单，是**有序结构**：先说什么、后说什么、每段承担什么职责、段与段怎么接。

## 1. 两段式：离线入库，在线匹配

| 阶段 | 做什么 | 频率 |
|---|---|---|
| 离线 | 采集榜单内容 → ASR / OCR / 切分 → 逐段标 role → 归并 → 聚合 | 每批 / 每周 |
| 在线 | 平台 + 类目召回 → 硬筛 → 打分 → 取前 3 → 改造清单 → 注入 | 每次生成 |

**硬约束**：在线不跑视觉解析、不回查原视频、不调分析类模型。所有重活留在离线。

POC 只做在线匹配这一段：离线骨架结果以 Mock 表提供。

## 2. 字段三组与边界

| 分组 | 回答什么 | 是否参与骨架表达 |
|---|---|---|
| 基础字段 | 这条是谁的、从哪来、属于什么类目 | 否，检索与追溯用 |
| 适配字段 | 这条骨架要求创作者具备什么（`creator_req`、`content_form`） | 否，取用时先筛后改造 |
| 核心字段 | 先说什么、后说什么、节奏怎么走（序列、钩子、收尾、节奏、篇幅） | 是，只有这组叫爆款逻辑 |
| 入口与要素 | 点不点进来、信不信（标题、封面、明星脸等） | 不落库，需要时临时解析 |

「像不像这个达人」由适配字段判断，「怎么讲」由核心字段判断，两者不能混。

## 3. 图文骨架字段

单位是页。每页记录三件事：承担什么职责、有没有产品、配了多少字。

| 字段 | 取值 | 说明 |
|---|---|---|
| `content_id` | md5 前 12 位 | 一条内容一行，重复抓取只更批次 |
| `platform` | `xhs` / `dy` | 平台 |
| `publish_time` | 时间戳 | 时效判断，近 90 天内才召回 |
| `category` | 继承 M4 品类树 | 如「食品-咖啡饮品」 |
| `context_type` | `daily` / `brand` / `node` / `unknown` | 日常 / 商单 / 节点 |
| `content_form` | `list` / `tutorial` / `review` / `vlog` / `story` / `info` | 形态，硬筛用 |
| `creator_req` | `{on_camera, text_heavy, scene_cnt, skill_level}` | 对创作者的要求，不是作者属性 |
| `page_roles` | `[{idx, role, text_len}]` | **骨架本体**：有序页序列 |
| `hook_type` | `conclusion_first` / `question` / `conflict` / `number` / `scene_entry` | 首段钩子句式 |
| `ending_type` | `product_shot` / `result_compare` / `cta` / `list_end` / `none` | 收尾类型 |
| `hook_sync` | 0 / 1 | 封面、标题、首句是否同指一件事 |
| `pace_shape` | `front_loaded` / `even` / `build_up` | 密度分布形状，不用均值 |
| `text_len_total` | 整数 | 正文字符数，与篇幅门槛 |

`role` 只取五类：`hook` 钩子 / `pain` 痛点 / `product_in` 产品出场 / `proof` 证据（含对比、实测、数据、资质）/ `ending` 收尾（含利益点、号召、成品展示）。首段恒 `hook`、末段恒 `ending`，模型只判中段。

`page_seq` 旧字段已废弃，由 `page_roles` 取代；页数由数组长度派生，不另存。

## 4. 视频骨架字段

单位是段（beat），一段可含多个镜头；镜头密度单独放节奏字段，不与段混。

| 字段 | 取值 | 说明 |
|---|---|---|
| `beat_roles` | `[{idx, role, start_sec, end_sec}]` | **骨架本体**：有序段序列，段数 4–8，单段不短于 1.5s |
| `creator_req` | `{on_camera, voiceover, speech_rate_band, demo_hands, scene_cnt, cut_skill}` | 语速档：slow <150 / medium 150–220 / fast >220 字每分 |
| `hook_type` | 同图文 | 对应首段 |
| `ending_type` | `product_shot` / `result_compare` / `cta` / `loop` / `none` | 视频多一个 `loop` 首尾呼应 |
| `hook_sync` | 0 / 1 | 首帧与首句口播是否同指 |
| `cut_rate_3s` | 前 3 秒镜头数 ÷ 3 | 留存直接指标，不用全片平均 |
| `pace_shape` | 同图文 | 前 3 秒、中段、末 5 秒切镜率比较 |

视频不存时长：时长取 `beat_roles` 末段 `end_sec`，由代码派生。

## 5. 匹配七步

| 步 | 做什么 | 判据 | 不满足 |
|---|---|---|---|
| 1 召回 | 按平台、类目、形态、时效取候选 | 平台相同；类目同主类目或相邻；形态同或相邻；近 90 天 | 放宽到相邻类目；仍无则跳过骨架参考 |
| 2 硬筛 | 剔除不可执行 | 达人历史有该 `content_form`；篇幅不超过中位数 2 倍；语速差不超过一档 | 任一不满足即剔除；**出镜冲突不剔除，记改造清单** |
| 3 打分 | 四项加权 | 类目 40 / 形态 25 / 节奏 20 / 钩子 15 | 得分只用于同批排序 |
| 4 取前三 | 按分取 3 条 | 同分时 `publish_time` 新的优先 | 不足 3 条不补齐，宁少不凑 |
| 5 改造清单 | `creator_req` 与画像逐项比 | 出镜、口播、语速、手部演示、场景数、剪辑难度、篇幅 | 差异 > 2 项 → 降级为参照，不进注入 |
| 6 注入 | 拼结构块 | 只给段序、职责、三项硬约束 | 不给原文、不给作者信息 |
| 7 留痕 | 记录本次骨架 | `content_id`、改造项、后续表现 | 用于回头调权重 |

**三版互斥的取法**（POC 在“取前三”上加一层）：优先保证三条骨架的 `content_form` 与 `hook_type` 都不重复；不足时退一步只保证 `hook_type` 不重复；仍不足才按分数补齐。

## 6. 打分细则

| 维度 | 权重 | 一致 | 相邻 | 不一致 |
|---|---|---|---|---|
| 类目 | 40 | 同主类目 | 品类树相邻 | 跨类目 |
| 形态 | 25 | 同 `content_form` | 清单↔测评、教程↔科普 | 其余 |
| 节奏 | 20 | `pace_shape` 是达人历史众数 | 历史中出现过 | 没出现过 |
| 钩子 | 15 | 是达人最常用句式 | 出现过但非最常用 | 没用过 |

类目权重最高，因为跨类目的结构迁移率最低；节奏与钩子权重低，因为最容易改造。

## 7. 三条骨架 → 三版脚本

- 取到的 3 条骨架按分数排序，对应 `V1 / V2 / V3`。
- 每条骨架负责一版的**段序与职责**；语气、句式、语速、篇幅由画像决定。
- 骨架之间不得重合：钩子类型、收尾类型、内容形态尽量不同；三版主推卖点仍须各自不同。
- 若到第 4 条仍凑不齐 3 条 → 少出几版并说明，不硬凑。

## 8. 改造清单

逐项比 `creator_req` 与画像，写清“改什么、怎么改”：

| 项 | 图文 | 视频 |
|---|---|---|
| 出镜 | 是否必须真人出镜 | 同 |
| 口播 | — | 是否需要口播 |
| 语速 | — | 语速档 vs 达人语速（字/秒 → 字/分） |
| 手部演示 | — | 是否需要手部特写 |
| 场景数 | 需要几个拍摄场景 | 同 |
| 剪辑难度 | 制作难度 low / mid / high | 切镜难度 |
| 篇幅 | 正文字数 vs 达人中位数 | 时长 vs 达人中位数 |

改造项 > 2 项 → 该骨架降级为参照，不进入注入；换下一条候选。

## 9. 约束强度

| 级别 | 管什么 | 用法 |
|---|---|---|
| 硬约束 | 开头钩子类型、产品出场不晚于时长 40%、结尾类型 | 三项必须命中 |
| 软约束 | 中段 role 的先后、段数与段长、每段字数、carrier 组合 | 可调，允许合并与省略 |
| 不约束 | 具体表达、语气、镜头语言、道具与场景 | 完全交给画像 |

四条落地规则：

1. 段数给区间不给定值，模板记 4–8 段，允许合并相邻同角色段；
2. 字数与秒数用画像语速、本次时长现算，不抄样本；
3. 图文更松，允许两页并一页，页数按达人历史习惯；
4. 优先级：合规 > 甲方必讲点 > 达人本色 > 骨架，骨架永远排最后。

## 10. 注入结构块

生成前拼一段结构块，只含段序、职责与硬约束：

```text
骨架 xhs_5b21c7e4｜形态 测评｜6 页
段序：1 hook → 2 pain → 3 product_in → 4 proof → 5 proof → 6 ending
硬约束：钩子 conflict（冲突）；product_in 不晚于第 3 页（前 40%）；收尾 result_compare（效果对比）
软约束：中段 role 可合并，页数按本人习惯 3–6 页；篇幅按本人中位数现算
```

```text
骨架 dy_9d3f61ab｜形态 测评｜6 段
段序：hook → pain → product_in → proof → proof → ending
硬约束：钩子 conclusion_first（结论前置）；product_in 不晚于 40%（30s 档即 12s）；收尾 product_shot（成品展示）
软约束：相邻同角色可合并，段数 4–8；秒数与口播字数按 30s、4.2 字/秒现算
```

## 11. POC 命令与 Mock

```bash
python3 scripts/skeleton_pick.py --branch xhs
python3 scripts/skeleton_pick.py --branch video --topic "咖啡液平价替代：用平价替代算一笔账" --angle cheap_alternative
python3 scripts/skeleton_pick.py --branch xhs --all   # 看全部评分与淘汰原因
```

- 图文 Mock 7 条、视频 Mock 7 条：`references/mock/skeleton/mock-skeleton-xhs.json` / `mock-skeleton-video.json`。
- 字段全部按上表 Mock：`page_roles` / `beat_roles` / `hook_type` / `ending_type` / `hook_sync` / `pace_shape` / `creator_req` / `text_len_total` / `cut_rate_3s`。数值不代表真实榜单内容。
- 骨架失败或不足 3 条 → 用分支 schema 里的降级骨架（痛点共鸣 / 场景种草 / 测评对比），成品卡标注「本次未使用爆款骨架」。
